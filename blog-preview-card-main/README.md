Bem-vindo! 👋

Obrigado por conferir este desafio de código front-end.

Os desafios do Frontend Mentor ajudam você a melhorar suas habilidades de programação construindo projetos realistas.

Para fazer este desafio, você precisa de um conhecimento básico de HTML e CSS.

O desafio

O seu desafio é construir este cartão de prévia de blog e deixá-lo o mais próximo possível do design.

Você pode usar as ferramentas que quiser para ajudar a concluir o desafio. Então, se tem algo que gostaria de praticar, fique à vontade para experimentar.

Os usuários devem ser capazes de:

Ver os estados de hover e de foco (focus) de todos os elementos interativos da página
Quer ajuda com o desafio?

Entre na nossa comunidade e tire suas dúvidas no canal #help.

Onde encontrar tudo

Sua tarefa é construir o projeto seguindo os designs dentro da pasta /design. Você vai encontrar uma versão mobile e uma versão desktop do design.

Os designs estão em formato JPG estático. Usar JPGs significa que você precisará usar o seu melhor julgamento para estilos como font-size, padding e margin.

Se quiser o arquivo de design do Figma para ganhar experiência com ferramentas profissionais e construir projetos mais precisos mais rápido, você pode assinar como membro PRO.

Todos os recursos necessários para este projeto estão na pasta /assets. As imagens já foram exportadas no tamanho correto para cada tela e otimizadas.

Também incluímos arquivos de fontes variáveis e estáticas para as fontes exigidas neste projeto. Você pode escolher entre usar o link do Google Fonts ou usar os arquivos de fonte locais para hospedar as fontes você mesmo. Observe que removemos os arquivos de fonte estáticos dos pesos que não são necessários para este projeto.

Há também um arquivo style-guide.md com as informações de que você vai precisar, como a paleta de cores e as fontes.

Usando assistentes de código com IA

Incluímos dois arquivos para ajudar caso você use assistentes de código com IA (como Claude, GitHub Copilot, Cursor etc.) neste desafio:

AGENTS.md - Contém instruções detalhadas para assistentes de IA sobre como ajudar você neste desafio. Ele é adaptado ao nível de dificuldade do desafio, então a IA dará orientações adequadas ao seu estágio de aprendizado: mais apoio nos desafios para iniciantes e incentivo a mais independência nos avançados.
CLAUDE.md - Um arquivo de referência que direciona as ferramentas baseadas no Claude para as instruções do AGENTS.md.

Como usar: você não precisa fazer nada! Esses arquivos são detectados automaticamente pela maioria das ferramentas de código com IA. A IA vai lê-los e ajustar o comportamento para ser um parceiro de aprendizado melhor, guiando você até as soluções em vez de simplesmente entregar as respostas.

Observação: esses arquivos foram feitos para ajudar você a aprender, não para fazer o trabalho por você. A IA é instruída a fazer perguntas, dar dicas e explicar conceitos em vez de escrever soluções completas.

Construindo o seu projeto

Use o fluxo de trabalho com o qual você se sentir confortável. Abaixo há um processo sugerido, mas não sinta que precisa seguir estes passos:

Inicialize o projeto como um repositório público no GitHub. Criar um repositório facilita compartilhar o seu código com a comunidade caso você precise de ajuda. Se não souber como fazer isso, leia este material do Try Git.
Configure o repositório para publicar o seu código em um endereço web. Isso também será útil se você precisar de ajuda durante um desafio, pois poderá compartilhar a URL do projeto junto com a URL do repositório. Há várias formas de fazer isso, e damos algumas recomendações abaixo.
Analise os designs para começar a planejar como vai encarar o projeto. Esta etapa é fundamental para ajudar você a pensar antecipadamente nas classes CSS, criando estilos reutilizáveis.
Antes de adicionar qualquer estilo, estruture o seu conteúdo com HTML. Escrever o HTML primeiro ajuda a focar em criar um conteúdo bem estruturado.
Escreva os estilos base do projeto, incluindo estilos gerais de conteúdo, como font-family e font-size.
Comece a adicionar estilos pelo topo da página e vá descendo. Só passe para a próxima seção quando estiver satisfeito com a área em que está trabalhando.

Crie um README.md personalizado

Recomendamos fortemente que você substitua este README.md por um personalizado. Fornecemos um modelo dentro do arquivo README-template.md neste código inicial.

O modelo serve de guia para o que adicionar. Um README personalizado ajuda você a explicar o seu projeto e a refletir sobre o que aprendeu. Fique à vontade para editar o nosso modelo como quiser.

Depois de adicionar as suas informações ao modelo, apague este arquivo e renomeie o README-template.md para README.md. Assim ele passa a aparecer como o README do seu repositório.

Enviando a sua solução

Envie a sua solução na plataforma para o restante da comunidade ver. Siga o nosso "Guia completo para enviar soluções" para ver dicas de como fazer isso.

Lembre-se: se você quer receber feedback sobre a sua solução, faça perguntas ao enviá-la. Quanto mais específicas e detalhadas forem as suas perguntas, maior a chance de receber feedbacks valiosos da comunidade.

Compartilhando a sua solução

Há vários lugares onde você pode compartilhar a sua solução:

Compartilhe a página da sua solução no canal #finished-projects da nossa comunidade.
Compartilhe no X (antigo Twitter) e mencione @frontendmentor, incluindo as URLs do repositório e do site publicado na postagem. Adoraríamos ver o que você construiu e ajudar a divulgar.
Compartilhe a sua solução no LinkedIn.
Escreva um blog sobre a sua experiência construindo o projeto. Escrever sobre o seu fluxo de trabalho, as escolhas técnicas e explicar o seu código é uma ótima forma de reforçar o que você aprendeu. Boas plataformas para escrever são dev.to, Hashnode e CodeNewbie.

Fornecemos modelos para ajudar você a compartilhar a sua solução depois de enviá-la na plataforma. Edite-os e inclua perguntas específicas quando estiver buscando feedback.

Quanto mais específicas forem as suas perguntas, maior a chance de outro membro da comunidade dar um feedback.
